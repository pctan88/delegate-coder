# Decision log: dependency manifest guard

Append-only.

| # | Date | Decision | Context / why | Consequence | Owner |
|---|---|---|---|---|---|
| 1 | 2026-08-29 | **Implemented:** package.json version/downgrade guard, hooked in after syntax preflight and before `test_command` | Real dogfood (Lead Portal Angular 22 migration, logged 2026-08-28 in `AI/delegate-coder-qwen-findings.md`): worker chose an invalid Angular version and downgraded `keycloak-angular`; neither is a syntax error, so the existing preflight + test_command verification didn't catch either | New `DEPENDENCY_GUARD_FAIL` status; package.json contracts get a third, cheap, offline check before the expensive test command runs | Plugin owner *(confirm)* |
| 2 | 2026-08-29 | **Decision:** no registry-existence check (e.g. `npm view`) | Would add a network call the project's local-only privacy stance explicitly avoids (see docs/ai-first-contract-router); a syntactic semver check catches the hallucinated-version case without it | An installed-but-nonexistent version that is nonetheless valid semver syntax is not caught by this guard — relies on `test_command` (e.g. `npm ci`) to surface that case | Plugin owner *(confirm)* |
| 3 | 2026-08-29 | **Decision:** downgrade guard is opt-out per-package (`allow_downgrade`), not a global config toggle | A deliberate downgrade (security revert, compatibility pin) is a per-task decision the orchestrator should state explicitly in the contract it's authoring, not a standing repo-wide policy that could mask the next unintended downgrade | Every contract that legitimately needs to downgrade a dependency must say so explicitly | Plugin owner *(confirm)* |
| 4 | 2026-08-29 | **Decision:** verification timeout keeps `TEST_FAIL` status, adds a `Hint:` line only | Changing the status value itself would be a breaking change for any existing consumer of the contract report's `- Status:` field; the diagnosability gap was in the *message*, not the status taxonomy | Timeout is now human/orchestrator-diagnosable via the hint, with zero risk of breaking existing status-field parsing | Plugin owner *(confirm)* |
| 5 | 2026-08-29 | **Found and fixed (incidental, not part of the above):** `stat -f`/`stat -c` fallback order was BSD-first, which fails silently (not loudly) on Linux — GNU `stat -f` means "filesystem status" and exits 0 with unrelated output rather than erroring, so the intended `stat -c '%a'` fallback never ran | Blocked a clean self-test run on the Linux sandbox used to validate this feature; the same latent bug would affect the ubuntu leg of the CI matrix NEXT_STEPS.md calls for, silently breaking file-mode preservation | Reordered to try `-c` first (both in `contract-router.sh` and the two matching test assertions in `contract-router.test.sh` that shared the bug) | Plugin owner *(confirm)* |
